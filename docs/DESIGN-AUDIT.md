# Design audit — UI against `docs/DESIGN.md`

Prompt 0 (read-only). Audited 2026-10-27.

**Scope:** every page under `src/app/(dashboard)` and `src/app/(auth)`, every component under `src/components`, plus `src/app/globals.css`, `src/app/layout.tsx` and the layout primitives they render.

**Method:** static code review against the six checklist dimensions in Prompt 0. No source files were changed; this file is the only output. Findings were produced by four read-only review passes and consolidated, then the highest-impact claims were re-verified against the source (button sizes, missing route states, missing tokens, `navigator.onLine`, `aria-live`, nav role sets, sales pagination).

**Severity:**
- **Blocking** — stops a core task at 360 px, breaks spec §2 / §3 / §6 outright, or fails §10's definition of done at its root cause.
- **Should fix** — clear spec violation that does not stop the task. Where the root cause is a shared primitive (tokens, button/input sizes), call-site symptoms are listed as Should fix and point at the Blocking root row.
- **Nice to have** — polish or consistency.

**Prompt column:** 1 tokens/type/primitives · 2 shell + nav · 3 lists/tables/filters/pagination · 4 forms + sale flow + confirm sheets · 5 check-in screens · 6 poster · 7 dashboards/event pages · 8 tickets + print · 9 PWA · 10 a11y QA.

---

## The 5 worst problems

1. **The event-day check-in screens are off-spec end to end** (`src/components/check-in/scanner.tsx`). Not full-bleed (a `max-w-xl` bordered card with an `aspect-video` video); the result is a small inline box where **every failure shares one neutral style** (no red vs amber families), admitted has no check icon, no time, no vibration, no auto-clear; `role="status"` instead of `aria-live="assertive"` (no `aria-live` exists anywhere in `src`); offline is driven **only by `navigator.onLine`** with no server heartbeat, so a dead server on live Wi-Fi still shows a ready scanner; the manual serial input has no uppercase transform, no autocorrect off, no clear button. Spec §6 is the most critical section of the design. → **Prompt 5**
2. **There is no bottom tab bar and the role navigation does not match the spec** (`src/app/(dashboard)/layout.tsx:20-78`, `src/components/layout/nav-links.tsx:26`). Below `md` nav is a horizontally scrolling link row in the top header — Admin gets 11 items, Supervisor 7, Verifier 5, Seller 4, with primary actions off-screen. Seller has **no Sell tab** (`/sales/new` is unlinked) and no Tickets; Verifier lands on Overview instead of Scan; the sidebar appears at `md`, not `lg`. → **Prompt 2**
3. **The entire control layer is under the minimum size** (`src/components/ui/button.tsx:21-33`, `input.tsx:11`, `select.tsx:43`). Buttons default 32 px, `sm` 28 px / 12.8 px text, `xs` 24 px, largest (`lg`) only 36 px — **no 44, 48 or 56 px size exists**; inputs and select triggers are 32 px (spec: 48 px) and shrink to 14 px at `md`; labels/body text sit at 12–14 px. Touch-first §4 and §10 fail on every screen, including the login submit and scanner controls. → **Prompt 1**
4. **Brand and semantic tokens do not exist** (`src/app/globals.css:51-89`). Stock neutral shadcn palette — no `--brand-900/700/50`, `--gold-500`, `--ivory`, `--ink`, no `--success/--warning/--info` (grep across `src/` = 0 matches); `--primary` is near-black, background is pure white. Components hard-code `emerald/sky/amber/green-600` utilities inline; no `next/font`, no tabular numerals; `--ring` ≈2.4:1 and `text-muted-foreground` on `--muted` ≈4.3:1 are estimated AA failures. Spec §2 is unimplemented, so "success brighter than brand green" and "gold only on dark" cannot even be expressed. → **Prompt 1**
5. **No loading, error or not-found states anywhere.** Zero `loading.tsx` / `error.tsx` / `not-found.tsx` files under `src/app` (glob confirmed) and zero shared `Skeleton` / `EmptyState` / `ErrorState` components in `src/`. Every page awaits the database per request, so on the spec's "slow, flaky mobile data" the user gets a blank white page with no skeleton and no retry, and `notFound()` renders the bare Next 404 with no way back. Compounding it: the sales list shows "page X of Y" with **no Previous/Next/Load more — page 2 is unreachable from the UI** (`sales/page.tsx:47`). → **Prompts 1 + 2 + 3**

## What is already good (keep it)

- **No page-level horizontal scroll found** — every wide table is inside `overflow-x-auto`, and layouts use `min-w-0` / `flex-wrap` correctly (the violation is §5's "cards below `md`" pattern, not §3).
- **`min-h-dvh` / 100dvh** is used in the shell and auth layout; no `100vh` traps.
- **No genuinely hover-only affordances** — Base UI menus/selects open on tap; buttons have pressed + focus-visible states; nav has `aria-current` + active background.
- **Client-side form states are often solid**: login, batch-form, sale-create-form, event-form, ticket-actions and the scanner all have busy spinners, `FormAlert`/`role="alert"` errors and success toasts; `revoke-ticket-dialog` is the reference pattern for destructive confirms (serial shown, reason required).
- **Idempotency handling is correct and untouched**: sale creation and payment keep the `Idempotency-Key` across network failure and rotate only on definitive rejection; the scanner holds token + key in refs for retry. No UI change should alter this.
- **Permission gating is server-side** (`can(ctx.role, …)` in server components); nav visibility is UX only, as required.
- **No failure result ever gets green styling or the word "admitted"** — the gap is the inverse (failures are under-styled, successes are under-featured).
- **Toasts already use icon per type** (`sonner.tsx`) — colour is never alone there.
- **Scanner has permission-denied / camera-error / paused / network-error copy** and holds QR library loading behind a dynamic import.
